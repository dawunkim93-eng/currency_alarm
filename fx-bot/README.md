# 💱 환율·테더 알림 봇

달러(USD/KRW)와 테더(USDT/KRW)를 같이 보고 있다가, **갈아탈 만한 폭이 벌어지면**
텔레그램으로 알려주는 봇입니다.

전략은 두 갈래입니다.

| 신호 | 뜻 | 하는 일 |
|---|---|---|
| **달러 → 테더** (역프) | 테더가 은행 달러보다 싸다 | 은행 달러를 팔고 테더로 갈아탄다 |
| **테더 → 달러** (김프) | 테더가 은행 달러보다 비싸다 | 테더를 팔고 은행 달러로 돌아온다 |
| **은행 간 차이** | 매수 싼 곳과 매도 비싼 곳이 벌어졌다 | 싼 데서 사고 비싼 데서 판다 |
| **거래소 간 차이** | 업비트·빗썸 테더 값이 다르다 | 참고용 (전송 시간·출금 수수료 있음) |
| **급등·급락 / 지정가** | 기준율이 크게 움직이거나 목표가에 닿았다 | 매매 판단 |

## 수익률을 어떻게 계산하나

퍼센트는 **수수료와 스프레드를 다 뺀 뒤**의 값입니다. 그러지 않으면 0.05%짜리
차익이 전부 허깨비가 됩니다.

```
달러 → 테더 = (은행에 달러 1을 판 원화) ÷ (테더 1개 사는 데 드는 원화) − 1
테더 → 달러 = (테더 1개 판 원화)        ÷ (은행에서 달러 1 사는 원화) − 1
```

- 거래소 값은 **호가창 최우선 호가 + 테이커 수수료**입니다 (체결가가 아니라 실제로
  체결될 가격).
- 은행 값은 **모형**입니다. 아래를 꼭 읽어주세요.

### ⚠️ 은행 환율은 모형입니다

토스·카카오뱅크·스위치원은 공개 시세 API가 없습니다. 그래서 이렇게 추정합니다.

```
매수 = 매매기준율 × (1 + 스프레드 × (1 − 매수우대율))
매도 = 매매기준율 × (1 − 스프레드 × (1 − 매도우대율))
```

- 매매기준율: 하나은행 고시 (두나무 CDN, 실패 시 네이버 금융)
- 스프레드: `spread: null` 이면 하나은행 전신환 고시에서 역산 (보통 ≈1%)
- 우대율: `config.json` 에 직접 적습니다 (`0.9` = 90% 우대)

각 사가 자체 기준율을 쓰기 때문에 앱 화면과 몇십 전 어긋날 수 있습니다.
**실제로 찍힌 값을 봇에 알려주는 게 가장 정확합니다.**

```
/시세입력 토스 매도 1391.2
```

입력값은 기본 6시간 동안 모형보다 우선합니다. 우대율 자체가 바뀌었다면
`/우대 스위치원 매수 90` 으로 고정해 두세요.

## 시작하기

### 1. 봇 만들기

1. 텔레그램에서 [@BotFather](https://t.me/BotFather) → `/newbot` → **토큰** 복사
2. 만든 봇과 대화창을 열고 아무 말이나 보냅니다
3. chat id 확인:
   ```bash
   curl -s "https://api.telegram.org/bot<토큰>/getUpdates" | grep -o '"chat":{"id":[-0-9]*'
   ```

### 2. 설정

```bash
cp fx-bot/config.example.json fx-bot/config.json   # 우대율·임계값을 내 상황에 맞게
export TELEGRAM_BOT_TOKEN="123456:AAA..."
export TELEGRAM_CHAT_ID="123456789"                 # 쉼표로 여러 명 가능
```

### 3. 먼저 손으로 확인

```bash
npm run fx-bot:dry       # 텔레그램으로 안 보내고 화면에 출력 — 시세가 들어오는지 확인
npm run fx-preview       # 가짜 시세로 알림 모양만 미리보기 (토큰 불필요)
npm run test-fx          # 회귀 테스트
```

`fx-bot:dry` 에서 매매기준율과 업비트·빗썸 값이 찍히면 준비 끝입니다.

## 실행 방식

차익은 몇 분 만에 열렸다 닫힙니다. **계속 켜 두는 게 기본**입니다. 서버가 있으면
systemd·도커로, 없으면 GitHub Actions 안에서 상주시킵니다.

### GitHub Actions — 서버 없이 (공개 저장소 전용)

매시 정각에 봇을 켜서 **55분간 1분 주기로 감시**하다 스스로 종료합니다.
5분마다 단발 실행하는 것보다 훨씬 낫습니다 — 스케줄이 밀려도 상주 시간이
그 구멍을 덮고, 텔레그램 명령도 그동안 즉시 응답합니다.

워크플로는 `deploy/workflows/watch.yml` 이고, 켜는 절차(시크릿 등록·첫 실행)는
저장소 루트 README 에 있습니다. 상태(쿨다운·시세 기록)는 `fx-bot-state`
브랜치에 **1커밋으로 계속 덮어쓰며** 남습니다 — `actions/cache` 는 7일
미사용이면 사라져서 같은 알림이 다시 오는데, 브랜치는 그럴 일이 없고 저장소도
커지지 않습니다.

> ⚠️ **반드시 공개 저장소여야 합니다.** Actions 는 공개 저장소에서만 무료
> 무제한입니다. 비공개는 월 2,000분(무료 요금제)이라 상주는커녕 10분 주기
> 단발 실행도 한도의 두 배를 씁니다.
>
> 이 봇이 다른 저장소 안에 얹혀 있다면(비공개일 수 있으니) 워크플로는
> `.github/` 밖에 재워 둔 상태입니다. `deploy/split-to-own-repo.sh` 가 빈 공개
> 저장소로 떼어내면서 제자리로 옮겨 활성화합니다.

### systemd — 라즈베리파이·홈서버·VPS

```bash
sudo fx-bot/deploy/install-systemd.sh   # 유닛 설치 + /etc/fx-bot.env 생성
sudo nano /etc/fx-bot.env               # 토큰·chat id 채우기
sudo systemctl enable --now fx-bot
```

스크립트가 하는 일은 경로·계정을 채운 유닛을 설치하고 켜는 것뿐입니다. 여러 번
실행해도 이미 있는 설정은 덮어쓰지 않습니다.

```bash
journalctl -u fx-bot -f          # 로그
sudo systemctl restart fx-bot    # config.json 고친 뒤
systemctl status fx-bot          # 살아 있나
```

### 도커 — NAS·VPS

```bash
cp fx-bot/deploy/fx-bot.env.example fx-bot/deploy/fx-bot.env   # 토큰 채우기
cp fx-bot/config.example.json fx-bot/config.json
docker compose -f fx-bot/deploy/docker-compose.yml up -d
docker compose -f fx-bot/deploy/docker-compose.yml logs -f
```

상태(쿨다운·시세 기록)는 볼륨에 남으므로 컨테이너를 다시 만들어도 같은 알림이
두 번 오지 않습니다. 헬스체크는 상태 파일이 10분 안에 갱신됐는지를 봅니다.

### 죽어도 다시 뜨게

- systemd `Restart=always` / 도커 `restart: unless-stopped`
- 처리되지 않은 예외도 상태를 저장하고 **비정상 종료 코드로 나갑니다** — 조용히
  멈춰 있는 게 제일 위험합니다 (알림이 없는 건 "기회가 없다"와 구분되지 않습니다)
- 재시작 루프에 빠져도 시작 인사는 1시간에 한 번만 갑니다
- 5분에 10번 넘게 죽으면 systemd 가 멈추고 `failed` 로 남깁니다

> ⚠️ **같은 토큰으로 두 곳에서 돌리지 마세요.** 텔레그램 롱폴링이 충돌해
> (409 Conflict) 명령 수신이 끊깁니다. 봇이 로그에 그렇게 찍어 줍니다.

### 그 밖의 실행 방식

```bash
npm run fx-bot           # 터미널에서 직접 (Ctrl+C 로 종료, 상태는 저장됨)
npm run fx-bot:once      # 1회만 확인 (cron 용)
```

## 텔레그램 명령

| 명령 | 설명 |
|---|---|
| `/시세` | 은행·거래소 현재가와 각 전환 수익률 |
| `/신호` | 트리거별 현재 수치와 기준까지 남은 폭 |
| `/설정` | 임계값·우대율·음소거 상태 |
| `/임계 toTetherPct 0.25` | 임계값 변경 (즉시 적용·재시작 후에도 유지) |
| `/지정가 매수 1380` | 지정가 알림 (`/지정가 해제` 로 끔) |
| `/시세입력 토스 매도 1391.2` | 앱에 찍힌 실제 환율 반영 |
| `/우대 스위치원 매수 90` | 우대율 조정 |
| `/설정값 notional 20000000` | 기준금액·주기 등 변경 |
| `/음소거 60` · `/해제` | 알림 일시 정지 |

허용된 chat id 외에는 **응답하지 않습니다.** 토큰만 알면 누구나 말을 걸 수 있어서,
모르는 사람에게는 봇의 존재조차 알리지 않습니다.

## 알림을 언제 보내나

- **처음 뜬 신호**는 즉시
- 같은 신호는 `cooldownMinutes`(기본 30분) 동안 다시 보내지 않음
- 단, 직전보다 `escalationPct`(기본 0.1%p) 더 좋아지면 쿨다운을 무시하고 즉시
  (0.3%에서 알림 받고 0.9%까지 벌어지는 걸 놓치지 않으려고)
- 신호가 풀리면 "해제" 한 번
- `digest.everyMinutes`(기본 60분)마다 정기 요약 — 신호가 없어도 지금 어디쯤인지는 알려줌
- 조용한 시간(기본 23~7시)에는 요약을 쉼. 트리거 알림까지 멈추려면
  `quietHours.muteAlerts: true`
- 시세 수집이 3회 연속 실패하면 한 번 알림 (봇이 눈 감은 걸 모르는 게 제일 위험)

음소거 중에는 쿨다운 기록도 남기지 않습니다. 음소거가 풀린 직후 아직 살아 있는
신호를 다시 받기 위해서입니다.

## 파일

```
fx-bot/
  index.mjs           실행부 — 시세 확인 루프 + 명령 수신
  preview.mjs         알림 미리보기 (네트워크 불필요)
  test-signals.mjs    회귀 테스트
  config.example.json 설정 예시
  deploy/
    split-to-own-repo.sh   전용 공개 저장소로 분리 + 첫 푸시
    workflows/watch.yml    GitHub Actions 상주 (새 저장소에서 활성화된다)
    install-systemd.sh     상주 실행 설치 (systemd)
    fx-bot.service         유닛 파일 (경로는 설치 스크립트가 채운다)
    fx-bot.env.example     토큰 — /etc/fx-bot.env 로 복사해 채운다
    Dockerfile             의존성 없는 단일 이미지
    docker-compose.yml     상태 볼륨 + 설정 마운트
  lib/
    config.mjs        기본값·검증 (퍼센트/비율 혼동을 여기서 잡는다)
    sources.mjs       시세 수집 + 파싱 (파싱은 순수 함수라 테스트 대상)
    venues.mjs        거래처별 적용 환율 모형
    signals.mjs       트리거 판정 + 쿨다운 규칙 — 봇의 핵심
    state.mjs         기록·쿨다운·오버라이드 저장
    format.mjs        텔레그램 메시지
    telegram.mjs      Bot API (롱폴링)
    commands.mjs      명령 처리
```

## 면책

이 봇은 **시세를 계산해 알려줄 뿐, 주문을 내지 않습니다.** 은행 환율은 모형이고
거래소 호가는 순간값이라, 알림이 뜬 시점과 실제 체결 시점의 값은 다를 수 있습니다.
매매 판단과 그 결과는 본인 책임입니다. 외화·가상자산 거래의 세금·신고 의무도
직접 확인하세요.
